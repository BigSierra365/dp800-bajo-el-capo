# 005 · RAG: asesor de averías (bloque G)

## Entrada para specify

```text
Asesor de averías con RAG: responde preguntas sobre las averías de un modelo usando solo los datos recuperados de SQL Server.

Historias de usuario:
1. Como comprador (a través del comercial), pregunto qué averías suele tener un modelo concreto y cuánto cuestan, y recibo una respuesta basada en las averías registradas, con su coste estimado.
2. Como alumno, quiero ver claramente las cuatro partes: la pregunta, los documentos recuperados, el contexto enviado al modelo y la respuesta final.
3. Como alumno, quiero una pregunta de control sobre un modelo sin averías registradas, y que el asistente diga que no tiene datos en lugar de inventarlos.
4. Como alumno, quiero usar el asesor desde SSMS y desde la terminal.
5. Como alumno, quiero explicar la diferencia entre un LLM solo y el RAG (SQL Server + Vector Search + contexto + LLM).

Criterios de aceptación:
- Dos preguntas válidas y el caso de control, por las dos vías, con las cuatro partes visibles.
- La respuesta solo menciona averías y costes presentes en el contexto.
- El caso de control responde que no hay datos.
- Comerciales y mecánicos usan el asesor sin permisos directos sobre el modelo externo.
- Los errores de la llamada al modelo se controlan con un mensaje claro.
```

## Entrada para plan

```text
- ai/rag.sql:
  - Recuperación compartida: ia.sp_contexto_averias_vector (@vector NVARCHAR(MAX), @modelo NVARCHAR(100) = NULL, @top INT = 5). Devuelve las averías más cercanas por VECTOR_DISTANCE (limitadas al modelo si se indica, mediante taller.ModeloAveria) y los coches disponibles similares.
  - ia.sp_asesor_averias (@pregunta NVARCHAR(4000), @modelo NVARCHAR(100) = NULL, @top INT = 5): genera el embedding de la pregunta con AI_GENERATE_EMBEDDINGS, recupera con la misma lógica, construye el contexto (título, síntoma, solución, coste estimado, frecuencia, gravedad y riesgo) y llama a qwen2.5:3b con sp_invoke_external_rest_endpoint en https://localhost:11435/api/chat (stream false, temperatura 0, mensaje de sistema restrictivo). Devuelve cuatro conjuntos de resultados: pregunta, documentos recuperados, contexto y respuesta. Comprueba en una respuesta real la ruta JSON del texto antes de fijarla.
  - Contexto de ejecución: el procedimiento se ejecuta como el usuario ia_servicio (EXECUTE AS o el mecanismo documentado en Microsoft Learn), con los permisos necesarios para el modelo y el endpoint, para que comerciales y mecánicos no los necesiten.
  - Errores de la llamada con THROW 503xx.
  - Si el modelo no tiene averías, se llama igualmente al LLM con el contexto vacío, para demostrar que el prompt restrictivo funciona.
- ai/asesor_averias.ps1: parámetros -Pregunta, -Modelo, -Top y -Servidor. Embedding de la pregunta con Ollama (POST http://localhost:11434/api/embed), recuperación con ia.sp_contexto_averias_vector (vector como parámetro), mismo contexto y mismo prompt que la vía SSMS, y respuesta con Ollama (POST http://localhost:11434/api/chat, qwen2.5:3b, stream false, temperatura 0). Muestra las cuatro partes con encabezados.
- tests/tests_ia.sql: el asesor devuelve los cuatro conjuntos y el caso de control responde sin citar averías. Documenta el criterio usado.
- Evidencias: docs/evidencias/005-rag.txt con dos preguntas y el caso de control por las dos vías.
- Si el modelo de 3B se desvía del contexto, endurece el prompt de sistema (respuestas cortas, citar solo el contexto) antes de cambiar de modelo. Anota en docs/decisiones.md las pruebas y el motivo del prompt final.
```

## Criterio de cierre

- `run_all.ps1 -ConIA` termina sin errores.
- `docs/evidencias/005-rag.txt` contiene las cuatro partes para dos preguntas y el caso de control, por las dos vías.
